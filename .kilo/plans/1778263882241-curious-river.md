# Code Review & AGENTS.md Update Plan

## Summary of Uncommitted Changes

The working tree adds major new features alongside the existing agent-runtime platform:

1. **Attachments system** (new module + entity) — S3-compatible file storage with presigned URLs, references, soft-delete
2. **Task comments** (new entity + API) — Dual authorship (user/agent), attachment linking, SSE events
3. **Agent profile enable/disable** (`isEnabled` column) — Built-in profiles seeded, workspace-level overrides
4. **Bootstrap manifest** — Runner can sync managed OpenClaw bootstrap files from the API
5. **Chat attachments** — Messages can carry attachment IDs; runner materializes downloads in OpenClaw workspace
6. **Task chat sessions** — Reopen done tasks, continue in managed runtime with context injection
7. **Artifact migration to attachments** — Runtime job artifacts now stored via AttachmentsService; legacy local FS path removed
8. **MCP attachment tools** — 5 new MCP tools for listing/getting/referencing/uploading attachments
9. **"Content Creator" → "Social Media Agent"** rename + 4 built-in profiles seeded instead of 1

## Issues Found

### Critical / Bugs

1. **No workspace scoping on task update/delete (TasksController)**
   - `tasks.controller.ts:73-74` — `update(@Param('id') id, @Body dto)` and `remove(@Param('id') id)` use only `id`, ignoring `workspaceId`. Any authenticated user can update/delete a task in any workspace.
   - Fix: Pass `workspaceId` to the service and verify task belongs to workspace before mutating.

2. **No workspace scoping on task findOne (TasksController)**
   - `tasks.controller.ts:43-44` — `findOne(id)` doesn't check workspaceId. Any user can read any task.
   - Fix: Accept workspaceId and verify.

3. **Missing workspaceId parameter in agent-profiles update**
   - `agent-profiles.controller.ts:33` — The controller passes `wsId` now, but `dto.update(id, dto, wsId)` requires workspaceId. However, the existing `update(id, dto)` path (non-built-in) also needs workspace scoping for authorization.

4. **Agent-profiles `findEnabledByWorkspace` is inefficient**
   - Calls `findByWorkspace` (2 queries: workspace + built-ins) then filters in JS. The `mergeWorkspaceOverrides` logic + `findEnabledByWorkspace` filter should be a single DB query with an OR condition and `isEnabled = true`.
   
5. **`buildRuntimeChatContext` always sends context on every message**
   - `managed-runtime.service.ts:728` — The old code conditionally omitted context after the first message (`session.openclawSessionKey ? undefined : ...`). The new code always sends it, which is wasteful (especially `allowedAgentIds` + `enabledAgents` + `recentAttachments` queries on every chat message) and may cause token bloat in the LLM prompt.
   - Fix: Only send context on first message or when session context changes; cache attachments list.

### Medium / Design Issues

6. **`recentAttachments` in chat context is unbounded**
   - `attachments.list(workspaceId, {})` returns up to 100, then `.slice(0, 20)` in JS. This queries all active attachments in the workspace on every message.
   - Fix: Add a `limit` param to `AttachmentsService.list()` and query with `take: 20, order: { createdAt: 'DESC' }`.

7. **No MinIO bucket auto-creation guard in ObjectStorageService**
   - The `minio-init` container creates the bucket, but if the app starts before minio-init finishes, `putObject` will fail with NoSuchBucket.
   - Fix: Add `ensureBucket()` on first upload (call `HeadBucketCommand` / `CreateBucketCommand` if needed), or document that the app depends on minio-init.

8. **Memory leak in `chatStreams` Subject map**
   - `ManagedRuntimeService.chatStreams` is a `Map<string, Subject<any>>` that never cleans up completed entries. Over time this leaks memory.
   - Fix: Clean up subjects when sessions close or after a TTL.

9. **Memory leak in `TasksService.events` Subject map**
   - Same pattern — `Map<string, Subject<TaskEvent>>` never evicts workspaces.
   - Fix: Add ref-counting or periodic cleanup of idle subjects.

10. **`upload_attachment` MCP tool decodes base64 twice**
    - `mcp.service.ts:469` calls `Buffer.from(args.contentBase64, 'base64').length` to compute `sizeBytes`, then `attachments.uploadBytes` does `Buffer.from(dto.contentBase64, 'base64')` again inside.
    - Fix: Compute size once, or accept `sizeBytes` as an explicit param and validate against it.

11. **Bootstrap files are hardcoded strings in managed-runtime.service.ts**
    - ~120 lines of multiline template strings for 8 bootstrap files embedded in the service file. This will become unmaintainable.
    - Fix: Move to a separate config file (YAML/JSON) or template directory and load at startup.

12. **`TaskComment.authorAgentProfileId` has no foreign key constraint**
    - The entity stores a nullable UUID but lacks `@ManyToOne(() => AgentProfile)` + `@JoinColumn`. This means orphan references can exist.
    - Minor: Consider adding the FK, or at minimum document that it's intentionally loose for agent IDs like "orchestrator" (not a real DB row).

13. **Circular dependency risk: TasksModule ↔ ManagedRuntimeModule**
    - `tasks.module.ts` imports `ManagedRuntimeModule` (for createTaskChatSession), and `managed-runtime.module.ts` imports `TasksModule` indirectly (via the service). This circular import works because NestJS resolves it lazily, but it's fragile.
    - Fix: Extract `TaskChatSessionService` into a shared module or use `forwardRef`.

### Minor / Style Issues

14. **`managed-runtime.service.ts` is 940+ lines**
    - The file handles: instance management, job CRUD, chat sessions, commands, artifact upload, bootstrap manifest, SSE streaming, policy validation, and 120 lines of hardcoded bootstrap templates. It violates the "one service per domain" convention from AGENTS.md.
    - Fix: Extract ChatSessionService, BootstrapManifestService, and ArtifactService (or use the new AttachmentsService for artifacts).

15. **`ObjectStorageService` has no delete integration**
    - Soft-deleting an attachment marks it as deleted but never cleans up S3 objects. Over time this wastes storage.
    - Fix: Add `storage.deleteObject(key)` call in `softDelete()`, or add a scheduled cleanup.

16. **`AgentProfilesService.ensureBuiltInProfiles` is idempotent but inefficient**
    - It loops through 4 built-in profiles and runs potentially 5+ DB queries per profile due to legacy name matching with OR conditions.
    - Fix: Use a single bulk query upfront, then batch insert/update.

17. **Frontend `useAttachments.ts` has no error handling**
    - The `uploadFiles` and `downloadUrl` functions have no try/catch. Upload failure mid-stream will leave partial uploads stuck in `pending` status.
    - Fix: Add error handling, rollback pending attachments on failure.
