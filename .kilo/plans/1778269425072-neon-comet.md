# Plan: Upgrade Agent Memory System (Nexoria)

## Goal
Make agent memory actually work — daily memories, semantic long-term recall, profile persistence, and real-time memory creation by agents.

---

## Current State (Audit Summary)

The 4-tier memory schema exists but is mostly a facade:

| Tier | Populated? | Used? | Issue |
|------|------------|-------|-------|
| `profile` | No | Yes (loads empty) | Nothing ever creates `profile` tier entries. |
| `session` | No | Yes (leaks) | Query lacks `sessionId` filter — loads all sessions for user. |
| `daily` | Yes | Yes (stale) | `ReflectionService` stores raw tool sequences + output summaries. But loadTier loads last 30 entries with **no date bound** (not "today"). No compaction. |
| `long_term` | No | No | Nothing creates `long_term` entries. `MemoryContextBuilder` uses `confidence DESC` instead of semantic search (`<=>`). Embeddings are never generated. |

### Critical Bugs
1. **Session memory leaks across conversations** — `loadTier('session')` ignores `sessionId`.
2. **Long-term memory is dead** — no embeddings generated, no semantic retrieval in agent loop.
3. **Semantic search endpoint is mocked** — `mockEmbedding = random floats`.
4. **No MCP tool for memory creation** — agents cannot persist a fact during a conversation.
5. **Managed runtime (OpenClaw) bypasses 4-tier memory entirely** — only loads `recentChatTranscript(20)`.
6. **Daily tier is not "today"** — loads 30 most recent `daily` entries regardless of date.
7. **No promotion pipeline** — high-confidence daily facts never graduate to `long_term`.
8. **No confidence feedback loop** — `positiveUses`/`negativeUses` tracked but never affect ranking.

---

## Proposed Work

### Phase 1: Fix Retrieval ( correctness )

1. **Session-scoped filtering**
   - Add `sessionId` to `MemoryContextBuilder.loadTier()` for `tier === 'session'`.
   - If no session-tier entries exist, fall back to last 20 messages of the chat transcript (hydrate from DB on first access).

2. **Date-bound daily loading**
   - Filter `daily` tier to `createdAt >= now - 24h`.
   - If >20 entries in last 24h, take top 20 by `confidence DESC`.

3. **Wire long-term semantic search into the builder**
   - Generate an embedding for the user's current message (using OpenAI `text-embedding-3-small` via `LlmProviderFactory`).
   - Call `MemoryService.semanticSearch()` with that embedding in `MemoryContextBuilder.build()`.
   - Remove the mock endpoint logic.

### Phase 2: Populate the Tiers ( data flow )

4. **Profile memory creation**
   - In `ReflectionService.reflect()`, detect sentences that look like user preferences/facts (heuristic: "I prefer…", "My … is …", "Always …").
   - Store detected facts to `profile` tier with `confidence = 0.8`.
   - Also expose `create_memory` MCP tool so the orchestrator can explicitly persist facts.

5. **Daily → long-term promotion**
   - Add a NestJS cron task (`@Cron(CronExpression.EVERY_DAY_AT_2AM)`) in a new `MemoryPromotionService`.
   - Query `daily` entries with `positiveUses > 0` OR `confidence >= 0.9` and `createdAt < now - 7d`.
   - Summarize them via a lightweight LLM call or simple concatenation, store as `long_term` with generated embedding.
   - Delete promoted `daily` entries (or mark `expiresAt`).

6. **Managed runtime memory injection**
   - In `ManagedRuntimeService.buildRuntimeChatContext()`, call `MemoryContextBuilder.build(ctx)` and inject the formatted text into `instructions`.
   - This is the most important integration — it makes memory available in the OpenClaw chat path.

### Phase 3: Agent-Driven Memory ( interactivity )

7. **MCP tool: `create_memory`**
   - Register in `McpService` with schema: `{ content: string, tier: enum, type: enum, confidence?: number }`.
   - Execute body calls `MemoryService.create()`.

8. **MCP tool: `recall_memory`**
   - Schema: `{ query: string, tier?: enum, limit?: number }`.
   - For `long_term`, generate embedding and call `semanticSearch()`.
   - For other tiers, do text `ILIKE` search.
   - Returns memory list so the agent can dynamically recall during a run.

9. **Memory creation during agent loop**
   - Allow the agent to emit a special JSON action `{"action":"remember","content":"..."}` at any step.
   - `AgentExecutorService` intercepts this and stores to `session` or `daily` tier immediately.
   - Alternatively, rely on the MCP `create_memory` tool (simpler, no new protocol).

### Phase 4: Quality Loop ( reinforcement )

10. **Confidence decay & feedback**
    - In `MemoryService`, add a weekly cron that reduces `confidence` by 0.05 for entries with `negativeUses > positiveUses` and no `lastValidatedAt` in last 30 days.
    - Add endpoint for users to thumbs-up/thumbs-down a memory (increments `positiveUses`/`negativeUses`).

11. **Memory DTO / API improvements**
    - Add `PATCH /workspaces/:wsId/memory/:id` to update confidence/content.
    - Add `DELETE` endpoint.
    - Return `lastValidatedAt` and use counters in `MemoryResponseDto`.

## Open Questions for User

1. **Embedding provider**: Should we use OpenAI `text-embedding-3-small` (cheap, 1536 dims) or a local model? The repo already depends on `openai` for LLM calls.
2. **Managed runtime priority**: The OpenClaw chat path is the primary runtime. Should Phase 2 (managed-runtime memory injection) be moved to Phase 1?
3. **Daily promotion LLM**: Do we want an LLM call to summarize daily memories into long-term facts, or is simple concatenation enough for now?
4. **Memory visibility in UI**: Should the frontend get a "Memory" page where users can browse/edit their agent's memories? This is a separate frontend task not covered here unless requested.
5. **Scope**: This plan covers ~11 tasks. Do you want everything, or should we start with the critical 3–4 items (semantic search, managed-runtime injection, MCP `create_memory`, session fix)?

## Success Criteria

- [ ] Session-tier memory is scoped to the current chat session.
- [ ] Daily tier only loads entries from the last 24 hours.
- [ ] Long-term memories are retrieved via pgvector cosine similarity using real embeddings.
- [ ] Managed runtime (OpenClaw chat) injects 4-tier memory into every turn.
- [ ] Agents can create memories mid-conversation via MCP `create_memory`.
- [ ] Agents can recall memories dynamically via MCP `recall_memory`.
- [ ] High-confidence daily entries are promoted to long-term nightly.
- [ ] `semanticSearch` endpoint no longer uses mock embeddings.
