# Nexoria Agent System
## SaaS + Pro Agent

This branch implements the **Phoenix Pro** agent engine: a dual-tier architecture replacing OpenClaw with native Nexoria agent loops.

### Architecture

| Tier | Location | Runtime Mode | Tools |
|------|----------|--------------|-------|
| SaaS Agent | Inside API container | `native_saas` | Safe tools (riskLevel <= 2) |
| Pro Agent | External VPS / Docker | `native_pro` | Full tools (terminal, fs, sandboxed code) |
| OpenClaw | Legacy (deprecated) | `openclaw` | Via MCP proxy |

### Components Added

- **`packages/agent-core`** — Shared agent loop library (ReAct pattern, memory fencing, context compression, dangerous-pattern scanner).
- **`apps/api/src/modules/remote-agent`** — WebSocket gateway + command queue for Pro Agent control.
- **`apps/api/src/modules/agent-runtime/loop/agent-loop.service.ts`** — NestJS wrapper around `packages/agent-core` for SaaS mode.
- **`apps/pro-agent`** — Lightweight remote agent runtime skeleton (config, sync client, entrypoint).

### Key Decisions

- **AI SDK v3** — Plan references v6 APIs; codebase stays on v3.2.0 (`generateText` with `maxToolRoundtrips`).
- **Per-turn memory prefetch** — `MemoryManager.prefetch(userMessage)` loads 4-tier memory before every turn, not just at session start.
- **Context fencing** — Memory is wrapped in `<memory-context>` tags with a system note. A `StreamingScrubber` strips these tags from streamed output via `ManagedRuntimeService`.
- **Tool registration boundary** — Dangerous tools (`terminal`, `fs`, `execute_code`) are registered only in `apps/pro-agent`, never in the SaaS agent.
- **Approval gate** — Tools with `riskLevel >= 3` pause the loop and require user confirmation before execution.
- **Redis pub/sub** — Commands are pushed from the API to Pro Agents via Redis instead of DB polling.

### Database Changes

| Entity | Changes |
|--------|---------|
| `AgentProfile` | + `runtimeMode` (`openclaw` / `native_saas` / `native_pro`), + `planTier`, + `remoteConfig` |
| `AgentCommand` | New table — command queue (`chat` / `job`) with `FOR UPDATE SKIP LOCKED` claiming |

### Running the stack

```bash
# Install monorepo dependencies
pnpm install

# Build shared package
pnpm --filter @nexoria/agent-core build

# Start database, redis, minio, API, web, worker
docker compose up -d

# Start the Pro Agent (optional, profiled service)
docker compose --profile pro up -d pro-agent

# API on :3000, Web on :3001, Pro Agent connects via WebSocket to :3000
```
